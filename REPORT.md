## 4. Виправлення

Кожне виправлення — окремий коміт у гілці `lab7`.

### Fix 1. Рейтинг рахувався в кожному порівнянні сортування

- **Сценарій:** S2 (введення в пошук), сортування «Рекомендовані».
- **Причина:** компаратор сортування викликав `tutorScore` (прохід по всіх відгуках з `new Date` для кожного) двічі на кожне порівняння. Для 2000 репетиторів це ~20 000 порівнянь, тобто сотні тисяч зайвих перерахунків на кожну натиснуту клавішу.
- **Що змінено:** `src/utils/catalog.js` — рейтинг кожного репетитора рахується один раз у `Map`, а сортування лише порівнює готові числа.
- **Коміт:** `Fix 1: рейтинг рахується один раз перед сортуванням, а не в кожному порівнянні`

### Fix 2. Layout thrashing у `useBioClamp`

- **Сценарій:** S4 (скрол).
- **Причина:** для кожної видимої картки код по черзі знімав клас (запис), читав `offsetHeight` (читання), додавав клас (запис) і знову читав. Кожне читання після запису змушувало браузер синхронно перераховувати layout сторінки з 2000 карток — і так на кожну подію `scroll`. Саме це DevTools позначив як **Forced reflow** на базовій лінії.
- **Що змінено:** `src/hooks/useBioClamp.js` — спочатку тільки читання (`scrollHeight` > `clientHeight` при вже обрізаному тексті, клас не знімається), потім тільки запис класів `has-more`.
- **Коміт:** `Fix 2: useBioClamp спочатку читає розміри, потім пише класи — без forced reflow при скролі`

### Fix 3. Зайві перерендери всіх карток

- **Сценарій:** S3 (клік «в обрані»).
- **Причина:** при будь-якій зміні стану `App` (наприклад, обрані) список заново фільтрувався й сортувався, а всі 2000 карток рендерились знову, бо отримували нові стрілочні функції в пропсах — хоча змінилась лише одна картка.
- **Що змінено:** `TutorCard` обгорнуто в `React.memo`; колбеки стабільні (`useCallback`, `setSelectedId` напряму, картка сама передає `tutor.id`); `getVisibleTutors` загорнуто в `useMemo` з залежностями `[query, filters, sortBy]`.
- **Коміт:** `Fix 3: React.memo для TutorCard, стабільні колбеки і useMemo для списку — без перерендеру 2000 карток`

### Fix 4. Усі фото вантажились одразу

- **Сценарій:** S1 (завантаження).
- **Метрика:**

| Метрика | До | Після |
|---|---|---|
| Передано даних, МБ | 23,0 | 5,0 |
| Кількість запитів | 41 | 11 |

- **Доказ:** Network panel до (`report/baseline-network.png`) і після.
- **Причина:** 2000 `<img>` без `loading="lazy"` — браузер одразу качав усі 36 фото по 900×900 PNG (~21 МБ), навіть ті, що далеко внизу. Без `width`/`height` браузер не знав розмір фото до завантаження.
- **Що змінено:** у `TutorCard` — `loading="lazy"`, `decoding="async"`, `width`/`height`; у банера `Header` — `width`/`height` і `fetchpriority="high"`.
- **Коміт:** `Fix 4: lazy loading і розміри для фото, fetchpriority для банера`

### Fix 5. `new Intl.NumberFormat` на кожну ціну

- **Сценарій:** S1 (завантаження), рендер списку.
- **Причина:** `formatPrice` щоразу створював новий об'єкт `Intl.NumberFormat` (дорога операція — завантажуються дані локалі). На 2000 карток — 2000 створень за один рендер.
- **Що змінено:** `src/utils/format.js` — форматер створюється один раз на рівні модуля.
- **Коміт:** `Fix 5: Intl.NumberFormat створюється один раз, а не на кожну ціну`

### Fix 6. Браузер верстав і малював усі 2000 карток

- **Сценарій:** S1 (завантаження), також S2 і S4.
- **Причина:** навіть коли JS став швидким, браузер рахував layout і paint для всіх 2000 карток, хоча на екрані видно лише кілька.
- **Що змінено:** `src/styles/index.css` — для `.tutor-card` `content-visibility: auto` і `contain-intrinsic-size: auto 600px` (браузер пропускає картки поза екраном). У `useBioClamp` видимість перевіряється по самій картці, щоб не змушувати браузер верстати приховані картки.
- **Коміт:** `Fix 6: content-visibility для карток — браузер не верстає картки поза екраном`

## 6. Перевірено і свідомо не змінено

| Місце | Обсяг роботи | Чому не проблема |
|---|---|---|
| `buildSubjectOptions` / `slugify` (`utils/subjectOptions.js`) — довгий ланцюжок map/filter/sort/reduce і регулярки | 12 предметів | Виглядає важким, але обробляє лише 12 елементів; у Bottom-Up не помітний |
| `suggestNames` / `editDistance` (`utils/suggest.js`) — алгоритм з матрицею | ~70 унікальних слів | Працює тільки коли пошук нічого не знайшов, і порівнює короткі слова |
| `useReferenceData` — три послідовні `await` (виглядає як мережевий waterfall) | 0 мережевих запитів | Дані беруться локально через `Promise.resolve`, у Network запитів немає — чекати нема на що |
| `Filters` — підрахунок кількості по предметах через `reduce` на кожен рендер | 1 прохід по 2000 об'єктів | Простий лінійний прохід, частка в трейсі мізерна |
| Сортування відгуків у `TutorDetails` | до 36 відгуків | Виконується лише для одного відкритого репетитора |
