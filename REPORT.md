## 4. Виправлення

### Fix 1. Рейтинг рахується в кожному порівнянні сортування

- **Сценарій:** S2 (введення в пошук), сортування «Рекомендовані».
- **Метрика:** найдовша взаємодія … → … мс; сума long tasks … → … мс.
- **Доказ:** у Bottom-Up до виправлення вгорі `weightedRating` / `tutorScore`, викликані з `sort`. `report/fix1-before.png`, `report/fix1-after.png`.
- **Причина:** компаратор сортування викликав `tutorScore` (а він проходить по всіх відгуках і створює `new Date`) двічі на кожне порівняння. Для 2000 репетиторів це ~20 000 порівнянь, тобто сотні тисяч зайвих перерахунків на кожну натиснуту клавішу.
- **Що змінено:** `src/utils/catalog.js` — рейтинг кожного репетитора рахується один раз у `Map`, а сортування лише порівнює готові числа.
- **Коміт:** …

### Fix 2. Layout thrashing у `useBioClamp`

- **Сценарій:** S4 (скрол), також S2.
- **Метрика:** сума long tasks при скролі … → … мс.
- **Доказ:** у трейсі до виправлення — багато фіолетових блоків Layout з попередженням «Forced reflow» всередині обробника `scroll`. `report/fix2-before.png`, `report/fix2-after.png`.
- **Причина:** для кожної картки код по черзі знімав клас (запис), читав `offsetHeight` (читання), додавав клас (запис) і знову читав. Кожне читання після запису змушувало браузер синхронно перераховувати layout сторінки з 2000 карток — і так на кожну подію `scroll`.
- **Що змінено:** `src/hooks/useBioClamp.js` — спочатку тільки читання (`scrollHeight` > `clientHeight` при вже обрізаному тексті, клас не знімаю), потім тільки запис класів `has-more`.
- **Коміт:** …

### Fix 3. Зайві перерендери всіх карток

- **Сценарій:** S3 (клік «в обрані»).
- **Метрика:** тривалість кліку … → … мс; у React Profiler кількість відрендерених `TutorCard` 2000 → 1.
- **Доказ:** React Profiler (dev) до/після: `report/fix3-profiler-before.png`, `report/fix3-profiler-after.png`; трейс Performance (prod): `report/fix3-before.png`, `report/fix3-after.png`.
- **Причина:** при будь-якій зміні стану `App` (наприклад, обрані) список перераховувався й сортувався заново, а всі 2000 карток рендерились знову, бо отримували нові стрілочні функції в пропсах.
- **Що змінено:** `TutorCard` обгорнуто в `React.memo`; колбеки стабільні (`useCallback`, `setSelectedId` напряму, картка сама передає `tutor.id`); `getVisibleTutors` загорнуто в `useMemo` з залежностями `[query, filters, sortBy]`.
- **Коміт:** …

### Fix 4. Усі фото вантажаться одразу

- **Сценарій:** S1 (завантаження).
- **Метрика:** передано даних 23.0 → 5.0 МБ; запитів 41 → 11; LCP 1,7 → 1,9 с.
- **Доказ:** Network panel (фільтр Img) до/після: `report/fix4-before.png`, `report/fix4-after.png`.
- **Причина:** 2000 `<img>` без `loading="lazy"` — браузер одразу качав усі 36 фото по 900×900 PNG (~21 МБ), навіть ті, що далеко внизу. Вони конкурували за мережу з банером (LCP). Без `width`/`height` браузер не знав розмір фото до завантаження.
- **Що змінено:** у `TutorCard` — `loading="lazy"`, `decoding="async"`, `width`/`height`; у банера `Header` — `width`/`height` і `fetchpriority="high"`.
- **Коміт:** …

### Fix 5. `new Intl.NumberFormat` на кожну ціну

- **Сценарій:** S1 (завантаження), рендер списку.
- **Метрика:** TBT … → … мс; self time `formatPrice` у Bottom-Up … → … мс.
- **Доказ:** Bottom-Up до/після: `report/fix5-before.png`, `report/fix5-after.png`.
- **Причина:** `formatPrice` щоразу створював новий об'єкт `Intl.NumberFormat` (це дорого — завантажуються дані локалі). На 2000 карток — 2000 створень за один рендер.
- **Що змінено:** `src/utils/format.js` — форматер створюється один раз на рівні модуля.
- **Коміт:** …

### Fix 6. Браузер верстає й малює всі 2000 карток

- **Сценарій:** S1 (завантаження), також S2.
- **Метрика:** LCP … → … мс; TBT … → … мс; найдовша взаємодія в S2 … → … мс.
- **Доказ:** у трейсі до виправлення — довгий фіолетовий Layout після рендеру. `report/fix6-before.png`, `report/fix6-after.png`.
- **Причина:** навіть коли JS уже швидкий, браузер рахував layout і paint для всіх 2000 карток, хоча на екрані видно ~6–9.
- **Що змінено:** `src/styles/index.css` — для `.tutor-card` `content-visibility: auto` і `contain-intrinsic-size: auto 600px` (браузер пропускає картки поза екраном). У `useBioClamp` перевірка видимості — по самій картці, щоб не змушувати браузер верстати приховані картки.
